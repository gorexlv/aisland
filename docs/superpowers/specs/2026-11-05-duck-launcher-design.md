# Duck 启动器：以窗口为起点的批注与 OCR

日期：2026-11-05
范围：`outputs/DuckIsland`

## 为什么

Duck Island 的定位从"刘海上的一组工具"转为"桌面工作代理"：一个有形象的数字人，被唤起后挂（attach）到某个应用窗口上替用户干活。交互起点因此从"先选工具、再选窗口"倒过来，变成"先选窗口、再确定意图"。

这一版只做第一步：用新的入口和 attach 逻辑，把已有的**批注（批阅）**和 **OCR（读屏）**两项能力兜住。会议、盯消息、投递上下文、虚拟声道发言等后续能力不在本版实现，但设计不能把它们的路堵死。

## 目标

1. 一个全局快捷键唤起的启动器模态框（布局方案 A：原地切换两步）。
2. 启动器第 1 步列出窗口，当前前台窗口固定在第一位并默认选中。
3. 第 2 步列出该窗口可用的能力（本版：批注、OCR），推荐项默认高亮。
4. 选中的窗口、能力以标签形式进入输入框；用户可继续输入文字，也可直接回车执行。
5. 执行后，数字人以现有批阅的 attach 方式挂到目标窗口上，批注和 OCR 都走这条路径。
6. 刘海功能面板移除"读屏""批阅"两个挂件，只保留"会议"。

## 非目标

- 会议、Lark/微信消息监听等应用相关能力（本版启动器里不出现）。
- 用模型理解自由文字意图、用模型识别窗口场景。
- 工具调用、共享记忆的界面。
- 投递上下文（脱敏后带到 Claude / ChatGPT / WorkBuddy）。
- 虚拟声道设备与代用户发言。
- 同时 attach 多个窗口。

## 反目标（做到了也算失败）

- 启动器打开慢、列表要等模型或截图才出现。
- 必须用鼠标才能完成；"快捷键 → 回车 → 回车"不能直接开始工作。
- 改造后批注现有能力（截图框选、语音/文字意见、历史、AI 总结、写入备忘录、发送 Claude/Codex、恢复）出现回退。
- OCR 现有保障（未识别到文字不建空记录、保存失败保留文字可重试、未保存替换前确认）丢失。

## 交互设计

### 唤起

- 全局快捷键 **⌥⇧ Enter** 唤起启动器（复用原"选择批阅窗口"键位，原含义被取代）。
- **⌥ Enter**（切换批阅/截新画面）与 **⌥ E**（结束目标窗口工作）保留，语义推广到"当前 attach 的工作"，见下文。
- 菜单栏原"选择批阅窗口 ⌥⇧ Enter"改为"唤起启动器 ⌥⇧ Enter"。
- 同一时间只有一个 attach 工作。已有工作时再次唤起启动器并执行新工作（无论换窗口、换能力还是都换），先保存并结束旧工作（等同 ⌥ E），再 attach 新工作；只按 Esc 关闭启动器则旧工作不受影响。第 1 步默认选中的仍是唤起前的前台窗口。

### 启动器模态框（方案 A）

屏幕中央的浮层，上方输入框，下方单一列表，列表内容随步骤原地切换。

```
┌──────────────────────────────────────────────┐
│ (头像) [Lark · 产品周会] [批注]  补充意图…    │  ← 输入框，标签 + 文字
├──────────────────────────────────────────────┤
│ 第 1 步：窗口                                 │
│ ▸ Lark · 产品周会            [当前]           │  ← 前台窗口固定第一
│   Safari · 需求文档                           │
│   Xcode · DuckIsland                          │
├──────────────────────────────────────────────┤
│ ↩ 选择 · ⌫ 返回 · Esc 关闭                   │
└──────────────────────────────────────────────┘
```

- **第 1 步·窗口**：列出可选窗口（沿用 `visibleScreenTargets` 的过滤规则）。唤起前的前台应用窗口排第一、标"当前"、默认选中；其余按现有顺序。每行显示应用图标、窗口标题、应用名。行内的能力徽标位预留给应用相关能力；本版只有通用能力，徽标位为空。
- **第 2 步·能力**：选中窗口后，窗口名变为输入框里的第一个标签，列表原地换成能力列表：「批注」「OCR 读屏」。推荐项排第一并高亮；本版默认推荐「批注」。
- 选中能力后，能力变为第二个标签；再按回车（或点击"开始"）执行。
- **输入文字**：
  - 在第 1、2 步，文字过滤当前列表（窗口标题、应用名、能力名都可匹配）。
  - 两个标签都齐后输入的文字，作为本次工作的"意图备注"随工作保存并显示在记录顶部；本版不做模型解析。
- **键盘**：↑↓ 移动，回车确认当前高亮项，退格在输入框为空时删除最后一个标签并回到上一步，Esc 关闭启动器。
- **快捷路径**：⌥⇧ Enter → 回车（选当前窗口）→ 回车（选推荐能力）→ 回车（开始）。
- 窗口列表与能力判断只使用本地规则，不调用模型、不截图，保证秒出。
- 没有屏幕录制权限时，在启动器内给出与现有一致的授权提示与打开系统设置入口。
- 没有可选窗口时，显示"没有可选窗口，请打开应用后重试"。

### 能力注册

能力以一张可扩展的表定义：每项能力有名称、图标、适用条件（对所有窗口，或按 bundle ID / 窗口标题规则匹配）、推荐权重、执行入口。本版表中只有「批注」「OCR 读屏」两项通用能力。后续 Lark 会议、Lark 聊天等应用相关能力通过向这张表追加条目接入，徽标显示在第 1 步窗口行上。

### Attach 后的数字人

执行后立刻开工：批注立刻截图进入批阅（与现在 `choose` 后自动进入一致）；OCR 立刻在目标窗口上出现框选画面。

沿用现有批阅的 attach 方式：头像悬浮在目标窗口内、可拖动、记住相对位置、随窗口移动缩放；窗口不可见时隐藏、关闭时撤下并保留已完成内容。

- 头像（中间）：点击执行当前能力的主动作。
  - 批注：进入/退出批阅（与现在一致）。
  - OCR：在目标窗口上框选读屏。
- 左侧圆形按钮：工作入口，显示当前能力及其记录/历史。
  - 批注：与现有"完成并查看历史"一致。
  - OCR：打开本次工作的读屏记录列表（本次 attach 期间每次框选的文字与区域图），可复制、定位文件、重新框选。
- 右侧圆形按钮：音频开关。
  - 批注：与现在一致。
  - OCR：默认关闭、不开麦。打开后启动 Mo 实时对话，上下文是本次工作最近一次识别出的文字（换一次框选，上下文随之更新）；对话内容显示在下方记录区。尚无识别文字时按钮置灰并提示先框选。
- 下方记录区：显示当前工作的实时内容。批注沿用现有内容；OCR 显示最近一次识别的文字（可编辑、复制，保存状态提示与现有读屏一致）。若用户填了意图备注，显示在记录顶部。
- **⌥ Enter**：批注下与现在一致；OCR 下等价于点头像，开始新一次框选。
- **⌥ E**：结束当前工作并从窗口撤下。
- 右键菜单：保留批注现有项；OCR 提供"重新框选""查看记录""结束并撤下"。

### OCR 行为细节

- 框选画面、识别、保存逻辑沿用 `ScreenReader` 的现有实现（窗口静态截图上拖框、本机 Vision 识别、保存到 `ScreenReads/日期时间-编号/`，含 `文字.txt`、`region.png`、`source.json`）。
- 未识别到文字不新建记录；保存失败保留文字并可重试；有未保存修改时再次框选，沿用现有"保留/另存/放弃"确认。
- 每次框选都重新截取窗口最新画面。
- 存储格式不变：每次框选仍是 `ScreenReads/` 下的独立目录，兼容旧记录和"最近记录"。若有意图备注，写入该次的 `source.json`（新增可选字段）。本次 attach 的记录列表只在内存中按本次工作汇总，结束后通过"最近记录"查看。
- attach 中的 OCR 与菜单栏"快捷框选取字"使用彼此独立的读屏状态，互不触发替换确认。

### 刘海与其他入口

- 刘海黄鸭点击后的功能面板只保留「会议」挂件；「读屏」「批阅」挂件移除。
- 会议流程不变。
- 菜单栏"快捷框选取字"（不绑定窗口的全屏框选 OCR）保留，行为不变。
- 菜单栏其他项保持不变；与"批阅"相关的条目文案按上述快捷键调整。
- 批注"恢复最近一次批阅"原先在选窗口阶段的侧栏里，启动器跳过了这个阶段。改为放到菜单栏（"恢复最近批阅"）和批注头像右键菜单中，保证不回退。

### 批注的意图备注

保存进批注会话存档（新增可选字段，旧存档照常读取），显示在记录顶部，并作为一行"意图"出现在复制文本、写入备忘录、发送 Claude/Codex 的内容开头；不进入 AI 总结的输入。

## 约束

- macOS 15+，Apple Silicon；SwiftUI + AppKit，与现有代码风格一致（紧凑写法、少注释）。
- 沿用 ScreenCaptureKit 权限与现有签名方式，不新增权限。
- 现有 `tests/` 下的回归脚本（尤其 `review-hotkey`、`review-orb-entry`、`review-orbit`、`review-window-controls`、`ux-render`、`sidebar-placement`）在改造后需继续通过，或按新行为更新断言。
- 当前工作区有大量未提交改动；实现开始前需与用户确认如何处理（先提交现状再开分支）。

## 留给实现者决定的

- 启动器面板的具体视觉尺寸、配色，与现有 `IslandStyle` 保持一致即可。
- 批注与 OCR 如何共用 attach 组件（抽出通用"attach 会话"，还是让 OCR 复用 `ReviewPanels` 的定位与跟踪）。要求是两者外观与跟随行为一致，且不引入批注回退。
- OCR 记录列表的具体呈现形式。
- 如何获取唤起前的前台窗口（如在唤起时记录 frontmost application 与其最前窗口）。

## 我（Claude）做的决定，请确认

- 两个标签都选好后输入的文字只作为"意图备注"保存展示，不做模型解析。
- 本版默认推荐「批注」。
- OCR 音频对话默认关闭。
- 新工作替换旧工作时，旧工作保存并结束，不在后台保留。
- OCR 不新增会话级存储，本次记录列表只在内存。
- "恢复最近批阅"移到菜单栏和头像右键菜单。
- 意图备注进入导出内容开头，不进入 AI 总结。
- attach OCR 与"快捷框选取字"状态互相独立。
- 应用内显示名沿用现有的 "Mo · 墨" 与现有头像，不在本版改名。
- 菜单栏"快捷框选取字"保留。
